### **Project Goal**

To evolve a semantic search application for Quranic root words into an advanced, AI-powered chat application that provides personalized Quranic name suggestions, leveraging a Large Language Model (LLM) for intelligent curation and validation.

### **Current Architecture & Features**

**1. Backend API (FastAPI)**

*   **Endpoint:** `/api/search`
*   **Functionality:** Provides semantic search for Quranic root words based on an English query.

**2. Database & Search (PostgreSQL with `pgvector`)**

*   **Schema:** Stores pre-computed embeddings for Quranic word occurrences.
*   **Search Method:** Uses `pgvector`'s `.cosine_distance()` for efficient vector similarity search.

**3. Frontend (HTML, CSS, JavaScript)**

*   **UI:** A simple interface for entering a search query and viewing results in dynamically loaded cards.

---

### **Future Architecture & Features (Based on `claude-arch-plan.md`)**

**1. Core Philosophy: LLM as a Smart Curation Engine**

The central idea is to use an LLM not just as a generator, but as a sophisticated filter. It will take raw vector search results from the Quranic data and apply a strict set of rules to curate a list of appropriate, valid, and high-quality name suggestions.

**2. New Backend API (FastAPI)**

*   **Chat Endpoint:** A new `/api/chat` endpoint will orchestrate the entire process, from vector search to LLM filtering and personalization.
*   **Preference Endpoint:** A `/api/preferences` endpoint will capture user feedback (likes/dislikes) and reasons, which is crucial for personalization.

**3. Advanced LLM Integration**

*   **Strong Prompt Engineering:** The system will use a detailed "system prompt" with critical rules to guide the LLM, ensuring suggestions are grammatically correct, culturally appropriate, and religiously sound.
*   **Post-Processing Validation:** An additional layer of programmatic validation will be applied to the LLM's output to catch any errors and enforce safety constraints.
*   **Reason Categorization:** The LLM will also be used to dynamically categorize user-provided reasons for liking or disliking names, creating a structured dataset for deeper personalization.

**4. New Database Schema (PostgreSQL with `pgvector`)**

The database will be extended with new tables to support the chat functionality:

*   `name_suggestions`: To store the validated name suggestions generated by the LLM, including vector embeddings of their meanings.
*   `user_sessions`: To manage individual user interactions.
*   `user_preferences`: To store user feedback (likes/dislikes as a float score) on specific suggestions.
*   `preference_reason_categories`: To store the dynamic categories for user feedback.
*   `query_cache`: To cache LLM responses, improving performance and reducing costs.

**5. Vector-Based Personalization**

This is the most advanced feature. The system will:

*   **Store Preference Vectors:** Keep a record of the meaning embeddings for all names a user has liked or disliked.
*   **Boost Search Queries:** Use the user's preference vectors to influence the initial vector search, steering it towards results that align with their demonstrated tastes.
*   **Re-rank Suggestions:** Dynamically re-rank the LLM's suggestions based on their semantic similarity to the user's liked names before they are displayed.

**6. Frontend Chat Interface**

*   A new chat interface will be built to allow users to interact with the AI.
*   Name suggestions will be displayed in interactive "cards" with like, dislike, and report buttons.
*   Users will be prompted for reasons when they provide feedback.
